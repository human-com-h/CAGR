# Timing and complete cost protocol

Original runs: serial FP16 Qwen2.5-3B-Instruct, Transformers 4.51.3, PyTorch 2.11.0+cu128, Python 3.13.15; SDPA on `cuda:0` of a two-T4 host. The second GPU does not perform parallel inference. Batch and concurrency are both one. Freeze the complete software and CPU/storage environment before interpreting absolute times.

Model loading, native compilation, numeric checks, warmup, shared retrieval preparation, execution I/O and archival overhead are separate paid preparation ledgers. They are not zero. A short arithmetic generation warms the model; numeric/cache preflights are separately charged in historical runs. Each question's retrieval is warmed once outside the method path, and that cost is recorded separately. Eight normal methods follow the cohort's frozen rotated order. Two on/off pairs have balanced order per question. Technical executions are additional real executions, not free policy inference.

Within each method, end-to-end wall time includes the Pilot, continuation or discarded Pilot, answer re-generation, question rewriting, bridge probes (including rejected probes), retrieval, final generation, feature extraction and host decisions. SUGAR's semantic samples and same-backbone entailment calls are charged. Failures retain calls and partial wall time; missing backend cost is unknown, never silently zero. There are no automatic retries in the public driver.

`NativeStateGenerator` retains the original causal CPU/GPU interval accounting and deferred materialization. Production signal extraction adds no explicit device synchronization and records no CUDA events; ordinary required greedy token materialization still occurs. Do not add per-token `synchronize()` and then compare against the published timing. Component overhead is `routing_total_ms / end_to_end_ms` per question. Independent overhead is `(on_ms-off_ms)/off_ms`, averaged over the two pairs of each question before estimating uncertainty. Component P95 is not an end-to-end P95 ratio.

Use the original cohort-specific statistical functions in `tools/statistics_i.py` and `tools/statistics_ii.py`: 20,000 bootstrap resamples, seed 42, question as the unit. Paired quality/latency contrasts stratify by dataset and shard. Cohort I's historical component/on-off estimator uses the original unstratified question bootstrap within each requested population; Cohort II uses the registered stratified draw. Preserve this difference. Do not average two paired observations as independent test questions, pool the two cohorts, trim slow executions, or subtract supposedly free routing work.

No fresh latency tolerance has been measured for the new public adapter. Record hardware/software, clock conditions and full paid ledgers with each future run. Only the original fixed-path cost-substitution table is algebraic; it is not new hardware measurement.
